# 画布复用后的同帧工作诊断

产品未改动，仍为 PDF 画布复用 B 的 213 份来源。单独完成一份实际冻结 Electron 的 16 阶段完整 trace，五份测量脚本/固定夹具/画质相同；不混入此前十二轮普通资源统计。追踪真实工程/PDF 与父归档普通轮次的完整对象图复核通过。

新增分析器按主线程 RunTask 内 FireAnimationFrame 的最外层 FunctionCall 识别 PDF.js 续绘与共享前景回调，精确绑定实际 bundle 的一基行列、原文和 SHA；排除工作线程、内层重复调用并对嵌套根任务唯一归属。三项测试覆盖重复/工作线程、跨阶段裁剪/嵌套根和布局/GC 并集。这里的“同帧”是同一 RAF 根任务批次，不等同实际屏幕呈现帧或 GPU 栅栏。

| 阶段 | 有 PDF 续绘的根任务 | 其中两次续绘 | 同时有前景回调 | 最长根任务 |
| --- | ---: | ---: | ---: | ---: |
| 双页缩放 | 2 | 2 | 1 | 28.147 ms |
| 连续滚动 | 15 | 8 | 1 | 35.225 ms |
| 五次倍率稳定 | 3 | 1 | 0 | 28.904 ms（GC） |

双页最长根有两次 PDF 续绘（RAF 区间并集 7.558 ms）、一次前景回调；全部 RAF 15.767 ms、布局 3.314 ms、Commit 7.620 ms。另一个 21.736 ms 输入根任务没有 PDF RAF，布局并集 16.127 ms。连续最长根只有一次 PDF 续绘（5.038 ms），布局 13.795 ms、Commit 3.875 ms；第二长根 28.989 ms 才有两次 PDF 续绘。阅读倍率最长根的 X 编码 GC 并集 28.860 ms；独立 GC 工具同时分析其它配对编码。

这些嵌套类别可能重叠，禁止直接相加；根墙钟和采样栈不是 CPU 秒或能量。一次 profile 存在开销，不证明全部真实帧分布或因果。源码位置已经确认 PDF.js 的 onContinue 接收的是安排下一次原生 RAF 的回调；已有执行片目标约 15 ms、每十次操作检查，单个操作不可抢占。因此限同帧续绘只能覆盖部分停顿，还可能拆开原先共享的图层提交，增加总工作。

下一步先试固定尺寸页面的布局隔离，只考虑 layout/style 约束，保持像素与层序，严格画质先行；另保留公开 onContinue 的有界准入候选，首任务不额外强制等待一帧、避免无条件双 RAF，公平/优先级、取消、隐藏/交互恢复与最终完成必须验证。任何候选仍需整段普通 A/B 和总需求/延迟验收，不只看 callback 数量，也不通过关闭/强制 GC 把工作移出统计窗口。

父归档 MANIFEST/SOURCE-MANIFEST 保持不变并由哈希锚定，复用其完整来源、固定夹具、像素和普通导出；本目录收录原 trace、报告、九份分析及工具来源、实际 PDF.js 依赖源码、输出和测试记录。复核需要同一实际冻结运行目录：

```powershell
node scripts/archive-frame-budget.mjs --mode verify --runtime .cache/performance-pdf-display-candidate
```

复核全部原始/压缩哈希、父归档、307 个实际运行文件、源码映射、九份重算、三项测试和两份工程/PDF。重算时只替换临时 trace 路径，报告哈希仅在帧分析的临时输入中变化；原报告及其所有原始证据均保留。
