# 0.3.0 后的一轮内存/渲染优化

本轮未重开已经结束的 0.3.0 goal，也未重发安装包。每项工作负载只采一次 A/B，不取均值、不做能耗推断。

## 保留的改动

- PDF 半页预渲染与半页补全结束后，立即将临时 full-page/half-page canvas 置为 1×1，并解除完成的 RenderTask 引用。失败和取消也释放输出临时画布；跨缓存代际的可显示结果在卸载后释放。页面缓存仍为至少 15 张，加普通 200 MB / 节能 120 MB 的额外预算，缩略图仍为 150 张。
- `pdfInsertion.ts` 的 PDF 编辑库移入真正插页的异步调用。仅打开位图 OCR 窗口或解析页码不再求值 `pdf-lib`。
- OpenVINO 服务只在取得推理通道后，在工作线程导入对应 Texo/OPUS 引擎。OCR、健康接口和空服务不提前导入它们的 tokenizer/graph 模块。模型复用与默认 1800 秒闲置卸载政策不变。
- 本轮 OCR 选文层仅在选文工具启用且页面挂载时创建；词框宽度先批量读后批量写，悬浮光标变化不重建整层。批量 OCR 统计复用本次解析计划的位图几何，不二次遍历长文档 operator list。

## 单次证据和边界

`tests/render-memory-round.spec.ts` 使用 600×800 的 PDF，2× 半页预渲染后补齐整页，并与独立整页参考比较 RGBA SHA256。测试保留临时 canvas 的引用，验证释放不依赖垃圾回收：临时像素缓冲容量 **11,529,600 → 0 字节**（约 11.0 MiB）；整页尺寸均 1200×1600，最终缓存 11,520,000 字节、两次渲染，前后完整像素哈希一致。该数字不等同于整个 Electron 进程 RSS 下降，也不说明瞬时分配峰值完全消失；完整临时栅格仍用于保持像素一致。

`scripts/measure-native-service-idle.py` 在两个独立进程中各导入一次服务，不运行模型、不扫描设备、不调用 GC。Working set **66,625,536 → 64,716,800**，private bytes **284,856,320 → 283,607,040**。后端收益有限（约 1.8 MiB 工作集 / 1.2 MiB private）；不能外推为加载大模型后的降幅。单次导入耗时 **485.2 → 1761.8 ms**，未获得启动提速证据；延迟导入只是把不需要的工作从本阶段移开，首次使用对应功能仍须加载。

前后数据见同目录 JSON。渲染 A 的 `src/pdfRenderCache.ts` 与源提交 `13e93cf` 一致；B 为本轮源码。检查覆盖实际背景/高清块/缩略图恢复、文档切换释放、半页补全严格像素、插页保留表单/元数据以及后端任务准入、取消和模型切换。历史五个冻结基准脚本未修改。

本轮验证：71 个文件 / 403 项单元测试通过，TypeScript 与生产构建通过；Tesseract 实际三图识别、三种视图选词/复制、原图 OCR 信息、夜间/旋转页面、收缩工具条颜色/粗细/撤销重做、展开翻译和相关资源恢复回归通过。OCR 与 PDF 原生文字共享一个选文容器，保留旋转与原有选文命中逻辑。

## 依赖与后端的后续空间

删除未加载的包主要减少安装体积，不自动降低运行 RAM。已加载的浏览器模块不能靠关闭弹窗可靠卸载；大模型/推理堆更适合由可终止 Worker/子进程拥有。TixTab 已对多个模型实现闲置释放，继续优化应针对真实残留的会话/图缓存、PNG 解码缓冲和文档资源，不能用缩小用户要求的缓存或降低显示质量冒充优化。当前未替换 Electron/PDF.js，也不宣称达到原生阅读器的基础内存。

依据：[Electron 官方性能建议](https://www.electronjs.org/docs/latest/tutorial/performance)。
