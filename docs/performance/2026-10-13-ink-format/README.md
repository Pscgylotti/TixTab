# 导入追踪、测量方法修正与笔迹格式化实验

日期：2026-10-13。实验结论：**撤回笔迹格式化合并候选，保留磁盘路径导入的测量修正**。本轮没有保留新的应用渲染策略。

## 测量边界修正

旧基准通过 setInputFiles 的内存 buffer 传入 10.37 MB 工程。包含根任务的真实 Electron 追踪，在导入区间定位到 13,828,832 字节 DevToolsSession 载荷，接收消息约 841.2 ms、所在根任务约 844.7 ms。它属于自动化传输，不能归因于 PDF/对象绘制。先前合成矩阵“约 709 ms 导入尖峰”需要按此边界重新理解；旧固定工具的 A/B 仍可追溯，但整段值包含这项工具成本，不能作为真实用户导入或整段节能比例。

当前基准预先写好固定素材或使用 fixture-file 的原始路径，再由浏览器创建磁盘 File。实际文件读取、解析、保存、几何与渲染仍在统计内；没有把应用工作前移。磁盘追踪中导入区间最大 DevToolsSession 载荷 3440 字节、最大接收任务约 30.3 ms，最大应用根任务约 171.6 ms。方法修正不是应用优化，不能将两次工具的 CPU/时长差称作节能。根任务为墙钟时间，嵌套事件不可相加。

追踪脚本增加 toplevel/完整 timeline/V8 采样。分析器按 phase marker 的 renderer/main-thread Profile 选样，排除同 PID Worker；初版曾把 Worker 样本并入，现已纠正，独立合成追踪回归通过。原始三份追踪与精确 harness 归档，buffer/disk 两个旧 harness 的重建字节与原报告的组合哈希完全匹配。

## 单机制候选与决定

旧 ink.ts 为每个 outline 坐标生成路径字符串并计算边界时各调用一次 toFixed(2)。候选在一遍循环中同时写入路径字符串数组和边界，保留 toFixed/Number、原始点半径、压感、层序、画布像素与全部渲染策略。两份冻结构建 211 份来源仅 ink.ts 不同。

真实 Trace 单样本根任务约 171.6→150.3 ms，提示局部任务有所缩短；这不是完整流程收益。三组不带 Trace 的交错对照顺序 A1/B1、B2/A2、A3/B3，使用同一磁盘方法、高画质/quality、1440×960、DPR2.5，得到：

|指标（三轮中位数）|A|B|
|---|---:|---:|
|整段 CPU 秒|17.381|17.723|
|导入 CPU 秒|1.948|2.004|
|导入主线程任务秒|0.516|0.522|
|导入帧 P95 ms|8.800|16.800|
|导入帧 P99 ms|158.400|158.300|
|导入最大帧间隔 ms|174.900|174.900|
|导入 Long Task 最大时长 ms|132.000|113.000|
|200 ms 最大需求（核等效）|2.444|2.530|

整段 CPU 约 +2.0%、导入 CPU +2.9%、需求峰值 +3.6%；导入 P99/最大帧间隔基本不变，P95 更高。虽 Long Task 最大时长较短，未证明整体资源或流畅度收益，因此撤回。后台/温度未严格固定、只有三组，不将小差异解释为统计显著性。扫描和密集矢量各另有一组辅助运行，完整原始数据保留，不并入三组统计或据其选择有利结论。

质量与正确性：2000 条随机四类笔触/压力/坐标和 seeded/empty 路径，对独立旧路径及旧边界严格相同；包括空间索引共 8 项单元通过、类型检查通过。浏览器 CPU/GPU 严格光栅、实际编辑器、前景裁剪和导出共 4 项通过。实际候选 Electron 对冻结旧 ink.ts 的 12 项像素比较均为零差异，覆盖加载/书写/擦除/撤销/重做/夜间/视图恢复与上下文事件；上下文事件不是物理 GPU 重置，合成笔输入不是物理笔延迟。

归档含六份正式报告、四份辅助报告、三份追踪和分析、全部 src/配置快照与发生差异的运行代码。未改动模型/ORT/WASM 不重复分发；每份正式报告列全部实际运行文件哈希，通过冻结目录逐一读取验证。CPU 仅是未校准需求代理，其余能量项未知，不声称瓦特/焦耳/续航。
