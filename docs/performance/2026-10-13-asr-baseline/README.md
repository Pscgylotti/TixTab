# 本地语音资源基线与生命周期验证

这是第三轮专项的**基线与功能证据**，不是优化前后对照，也不代表第三轮或 0.3.0 已完成。原始报告含实际采样、阶段 CPU/内存/逻辑 I/O、模型版本与权重哈希、编译文件大小/时间戳及识别结果。17 份报告分为 7 组；冷 NPU/GPU 各一次，其余每组独立启动三次进程，不能把同进程内的重复识别视为独立样本。

## 实测条件与方法

- 当前 Windows 设备、8 个逻辑处理器；Python 3.10.5、OpenVINO/GenAI 2026.2、sherpa-onnx 1.13.8。详细版本在 `summary.json` 及原报告中。未调整电源计划、亮度或用户缓存。
- 使用已安装的固定版本模型，启动前核对清单中的 SHA256。Whisper INT8、256 token 上限、强制中英文、无时间戳；SenseVoice INT8、CPU 两线程、原解码参数。没有为跑分降低精度。
- 两段项目自编句子，经 Windows 桌面 TTS 生成 16 kHz 单声道 PCM：英文 4.965 秒，中文 4.735 秒。`evidence/samples.json` 保存声音名称、原句、文件大小和哈希；生成器位于 `sources/scripts/prepare-asr-samples.ps1`。未使用麦克风录音，未在仓库分发音频。换系统声音版本后生成的字节可能不同，应重新记录哈希。
- “cold”只表示独立编译目录为空，不表示操作系统文件缓存冷；“cached”是新进程读取已有编译文件；“warm”是同一模型实例内的后两次识别。每轮最后保留 5 秒常驻空闲、显式关闭模型、再保留 5 秒释放后空闲。
- 独立采样进程以 200 ms 为目标读取推理 Python 进程的累计 CPU、工作集、私有字节和逻辑 I/O。采样器成本另列，17 轮最大实际间隔均不超过约 234.2 ms。驱动/服务、硬件 GPU/NPU 活动和整机功率未采集。

## 结果

| Whisper / NPU / cached | 3 | 1780 | 2.016 | 182 | 208 | 1144 |

NPU cold 的 200 ms CPU 需求最高约 7.67 核等效，说明首次编译是应关注的资源尖峰。缓存组的两份 NPU blob 共 891492889 字节，三轮推理前后文件元数据不变；这支持磁盘复用有效，但没有编译器命中遥测，不能据此证明每个内部图都没有重新编译。此前已调整的缓存预算保留，不将旧改动单独算成此次第三轮优化。

GPU cold 推理期间继续生成小型 kernel cache；cached 第一轮有一个 138904 字节 `.onednn.cl_cache` 更新，后两轮没有变化。这不等于完整模型重新编译。GPU 显式关闭后进程工作集仍约 727 MiB，而 SenseVoice 约 60–61 MiB、缓存 NPU 约 162 MiB：`close()` 不一定把运行库/驱动保留内存全部还给系统，实际工作进程退出另行验证。

SenseVoice 的 5 秒常驻空闲阶段消耗约 0.359–0.375 CPU秒，逐样本定位在识别结束后的前约 400 ms，后续样本归零；不能描述成一直空闲忙转。后续候选是在保持线程数和推理参数的前提下，检查运行库线程空转控制并做独立 A/B。ONNX Runtime 提供线程空转配置，sherpa-onnx 对 `SessionConfig.` 配置有转发路径；当前生产代码尚未采用该候选。[ONNX Runtime 线程说明](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)，[当前运行库对应版本的配置代码](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/session.cc)。

两段干净 TTS 句子仅用于连通性和时延。Whisper 中文输出为繁体，原报告的字面字符距离包含简繁差异，不能把 8/15 直接解释成语义识别错误率，也不能用这两段材料宣称模型识别精度。

## 新的事件调度与真实协议验证

`asr_lifecycle.py` 将控制循环的 250 ms 活跃轮询改为实际完成事件、控制指令和录音截止时间唤醒；停止后等待完成，不再继续轮询。另修复完成状态与停止/策略指令竞态时未刷新闲置计时起点的问题。模型、音频处理和默认 1800 秒策略保持原参数，打包白名单包含新模块。

`verify-asr-lifecycle.mjs` 经实际 Electron 后端控制器调用 Python 工作进程，固定 WAV 取代麦克风：

- 英文首次准备约 2662 ms，第二次切换中文约 3 ms；两次会话共用一个 worker、仅一次 `loaded` 事件。
- 中文录音提前停止后返回已说出的文字，未丢弃最后一段。
- 测试策略设为 30 秒；最后一次会话完成约 30273 ms 后正常退出，退出码 0。下一次调用启动第二个 worker，准备约 3240 ms。测试结束将控制器策略恢复为 1800 秒，再销毁隔离服务。
- 生命周期四项检查、原语音后端七项检查、独立采样器一项真实 Windows 检查通过。采样器测试故意用持有 GIL 的原生阻塞调用，确认采样仍继续，并以实际 CPU 忙循环及 1 MiB 读写核对计数器。

这是功能/时序验证，尚无旧轮询与新事件机制的整段资源 A/B，不能由删除轮询推导出节能百分比。两分钟录音截止、处理中不按闲置卸载等边界由生命周期测试覆盖；自然 1800 秒到期没有在此等待完整半小时。

## 原始数据与复核
