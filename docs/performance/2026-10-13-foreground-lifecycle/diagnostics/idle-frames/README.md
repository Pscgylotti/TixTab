# 闲置与缩放尖峰：独立追踪及下一步设计

2026-10-13。沿用父目录生命周期实验的同一 A/B 冻结构建、五份测量脚本和混合工程，各执行一遍带 Chromium trace/V8 采样的完整 16 阶段流程。两份记录和普通六轮资源测量分开；当前产品来源仍为父实验保留的 B，未新增渲染策略。

基线闲置尾段在约 3.6 秒处存在 MajorGC，单个外层事件约 23.32 ms，JS heap 约 37.33→28.73 MB；同时有后台标记线程。GC 事件有大量嵌套，报告对区间先裁剪再取并集；不能把 607+ 个旧命名子事件的时间累加。最终工具扩展了 `V8.GC...` 增量/收尾命名覆盖，以上为最终重算值，早期结果/来源另存 `initial-gc`。异步 flow 和 instant 事件不当作持续时间，未配对 B/E 数为 0。

当前 B 的闲置尾段未识别到可计时 GC 区间，但双页缩放中存在 MajorGC（约 7.964 ms，heap 约 40.49→24.90 MB）及其它增量区间。因此 GC 会随工作与时间窗口变化，不能仅凭普通六轮 B1/B2 较高的闲置 CPU 就判定是新 hook 轮询，也不能凭这两份追踪就把此前全部差异定量归因于 GC。

追踪本身的开销明显：这里的闲置 renderer CPU 约 1.2–1.6 秒，远高于普通六轮约 0.023–0.219 秒；采样、记录、IPC 和其它线程工作都包含其中。区间并集是墙钟覆盖，不是 CPU 秒或焦耳；跨线程并集与各线程并集之和含义不同。主线程 TaskDuration 也不是全部 renderer CPU。

缩放最大根任务内没有可计时 GC，却同时包含 PDF.js 绘制、RAF 与底图 `drawImage`。其 V8 代表样本显示实际 ReadingPage 复制回调；当前 B 同一根任务还出现前景几何读取。整个阶段 `drawImage` 聚合采样约 A 9.384、B 18.196 ms，`getBoundingClientRect` 约 A 34.453、B 37.243 ms。采样可能合并多个调用者和 renderer 线程，不是独占函数 CPU 时间，不能与嵌套任务相加。

四个代表栈已绑定冻结 bundle 的 SHA256、零基行/列和原文片段：A/B 的 ReadingPage 复制及前景测量。这里只证明这些栈对应实际代码，不证明每个聚合叶样本都来自同一位置。两份 trace 的工程/PDF 导出也独立重建复核。

## 下一步实现优先级

1. **先减少背景 PDF 的显示复制。** 当前缓存提供已绘制的 Canvas，ReadingView、PdfSurface、DetailTile 又复制到显示 Canvas。试验复用已渲染画布的显式显示租约；同一源被多个视图使用时保留复制回退，不抢走其它视图的节点。任何显示端都不能清空/改尺寸来破坏共享缓存，旧画面保持到新结果就绪。还需覆盖 LRU 淘汰、取消、切页、主题、节点替换、卸载、GPU 上下文恢复与缓存所有权。先冻结试验并做严格像素/语义检查，通过后再完整资源 A/B；当前尚未实现或宣称收益。
2. **再验证完成发布的有界调度。** 若源画布复用不成立或仍有集中工作，可在新完成的 PDF 任务发布处做 FIFO 帧预算，保留缓存命中/已有预览的立即使用，不无条件给 PDF.js 已有续绘 RAF 再加一层。仅限制新任务发布不能声称所有消费者复制都被全局限制；多个消费者、隐藏/恢复、取消、最多两任务的内存和 45 秒可见截止必须独立验收。
3. **追踪真实分配来源。** 若需要进一步降 GC 成本，定位对象编辑、公式、保存及其它渲染的分配；不关闭 GC 或把强制 GC 移出测量窗口来制造收益。持续保留闲置尾段、隐藏/恢复和完成门槛，不只看活跃阶段的局部数字。

这些设计同时服务背景/前景分离优化，但不改变当前笔迹/对象层序或既定清晰度。前景稠密对象绘制、模型并发与真实能量仍是完整目标的后续工作，不因本次诊断缩小范围。
