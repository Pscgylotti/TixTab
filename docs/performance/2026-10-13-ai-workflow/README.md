# PDF 与真实本地语音并发流程

第三轮的一项优化：SenseVoice Small INT8 继续使用 CPU 两线程，仅关闭算子等待时的线程空转。A/B 用同一冻结 UI 构建 `cd0bcaf8fbd85eff7acee32218aee0041117735f5e8fee2faa9b1a122636f9ed`，两个后端只有 `asr-ort.config` 的 spinning 开关不同。模型、识别参数、PDF 画质和任务量均保持一致。单独语音的 12 轮及 8 个质量变体见[线程策略报告](../2026-10-13-asr-thread-policy/README.md)。

## 实际工作量和计量

真实 Electron 执行既定 40 页/3000 笔/80 对象流程：导入、书写、擦除、撤销、连续滚动、双页缩放、日夜切换、公式草稿、空闲和隐藏恢复。另一个实际 Python 后端加载固定权重，完整识别同一自编中文 WAV 十次，每次间隔 1 秒，随后常驻空闲 10 秒、释放模型、再空闲 10 秒。每轮都验证识别实际与连续滚动及双页缩放重叠，不能用两次独立测量相加冒充并发。

语音使用真实生产模型类和解码器，没有运行录音/UI IPC；PDF 输入为合成指针。这是可重复的并发压力用例，不是实际麦克风准确率或物理笔尖延迟测量。每个 PDF 阶段仍需任务台账、可见绘制就绪和稳定窗口检查；所有十次推理及空闲尾部必须结束后才汇总。

两条采样时间轴按各自单调时钟原点对齐；结束时观察到的墙钟偏差大于 5 ms 则拒绝。200 ms/1 s 窗口先积分各进程 CPU，再除以真实墙钟时长，不能把两个并发来源的覆盖时长相加作分母。独立采样器、协调器、启动准备、序列化、操作系统和驱动仍不在被测 CPU 合计内。CPU 窗口是采样间隔内的插值，不能证明更短尖峰。

联合 CPU 中位数约减少 17.3%，语音部分约减少 55.3%。各组件中位数不能相加来重建联合中位数；两个独立时间的工作集峰值也不能相加作为同时内存峰值。峰值范围重叠，后台和温度没有严格固定，不宣称统计显著性或整体内存降低。

十次识别在所有轮次文本一致。候选识别 P95 增加约 6 ms，连续滚动 P99 增加约一个 120 Hz 帧；双页缩放 P95/P99 接近。PDF 总 CPU 略高，夜间和公式阶段也有波动。因此暂保留线程等待策略，继续验证调度与长尾；这不是所有交互变快或第三轮已完成的证明。

## 保留的失败与计数器诊断

先前六轮保存于 `diagnostic/`，其中候选第一轮约 203 ms 的启动区间累计 CPU 倒退。新增拒绝门槛后重跑，四轮通过，第五轮再次因同一问题失败，完整报告/日志在 `diagnostic-recheck/`。原始 PID 和创建时间显示是同一进程的累计读数倒退，先前“进程切换”的初步判断已纠正；没有用钳制负值修补报告。

正式脚本在采样窗口前调用一次 `app.getAppMetrics()` 初始化计数器，后续异常仍拒绝。启动/初始化开销不被声称为已测量或优化；该准备操作两边相同。上述两个旧脚本精确版本随档案保留，和正式六轮分开，不根据结果优劣挑选通过轮次。[Electron CPU 指标定义](https://www.electronjs.org/docs/latest/api/structures/cpu-usage)说明累计时间的意义；此处首次异常的依据为保存的本机原始读数，没有推断其它版本也存在同样问题。

进一步回查 39 份历史渲染报告，7 份存在初始倒退区间，均为 setup/idle-before；详情在 `evidence/render-counter-audit.json.gz`。其中第一轮 `round1-1` 影响整段需求的完备性，原整段结论撤回；随后已[完整重跑三组](../2026-10-13-round1/recheck/README.md)，全部通过，以新公式阶段 -12.6% / 整段 -3.2% 恢复第一轮验收。旧有效阶段指标仍保留。早期 ink/spatial 的整段 CPU 比例也仅保留为不完整历史观察。第二轮 final、撤回的 memo 实验和保留的路径元素组均没有发现此缺口。未修改原始档案或虚构丢失的 CPU。

## 回退与复核

另用故障注入将设备枚举限定为 CPU，实际请求 Whisper NPU，确认生产实现回退 CPU 后完成中英文识别。不是禁用物理 NPU 或测试硬件损坏。首次测试助手用不完整的模拟 Core 导致初始化失败，诊断与修正后真实 CPU 的成功记录均已保留；该失败不计为生产回退故障。

`MANIFEST.json` 共 130 份文件：正式六轮、初始六轮、重查四轮及失败组件、组件日志、冻结后端、精确采样/比较/复核源码、回退和计数器审计。`UI-REFERENCE.json` 指向已归档的完整冻结 UI 源码与原生画质/首帧/导出证据，附来源哈希。

```powershell
node scripts/verify-ai-workflow-archive.mjs --production --frozen-ui .cache/performance-030-round2-path-cache-candidate
```

整机焦耳、GPU/NPU 活跃量与驱动用量不可得；不报告节能或续航比例。默认闲置卸载保持 1800 秒。其它本地 AI 后端、完整对象/扫描页矩阵、测量开销和最终便携包仍待专项验收，版本未发布。
