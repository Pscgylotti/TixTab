## 正确性证据与失败诊断

原有并发状态更新会让大幅滚动后的新内容晚一帧挂载。新增用例连续跳转 16 次，每次检查最早三个动画帧；修复前的第一个帧确有漏绘。现在共享视区的一次 RAF 内同步提交全部页面裁剪状态。修复前/后的逐帧原始 JSON 都保留在 `evidence/fast-jump-*`。

浏览器与真实 Electron 各三次完整用例通过；之后对**实际测得 B 冻结构建**和当前浏览器源码各补跑一次，包含完整 PDF 导出。每次完整用例在三种视图、日夜和滚动后比较原始全部对象参考画面；严格检查可见对象与笔迹没有遗漏、原始层序不变、已选对象离屏不被卸载。工程保持全部 120 个对象和 600 条笔迹。实际 PDF 导出再次检查 120 次对象绘制、600 条笔迹填充及笔迹上下的对象顺序，包含远离视区的对象。

原生 GPU 对不变场景的连续截图也曾出现末位通道变化，导致最初的逐字节稳定判定无法收敛。现有画面比对明确采用每通道最大 1/255 的上限，并同时要求几何/层序完全一致；不放宽大于 1 的差异。之前夜间边缘最大 25 的失败不被归为这种末位变化，也没有拿旧失败构建的数值代替修复后的复测。固定后浏览器与原生三次完整回归均通过，新的测得构建再验证通过。Canvas 增量/局部绘制的确定性回放测试仍要求逐通道零差异。

原生测试最初等待浏览器 `download` 事件，实际 Electron 保存走系统对话框，因此三次在保存步骤超时，前面的像素和首帧检查均已通过。测试改为截获实际编码得到的工程/PDF Blob，避免操作用户系统保存对话框；该失败日志及原始已完成检查另保留，不能计为三次端到端通过。

`MANIFEST.json` 记录原报告、压缩文件和证据哈希。`evidence/sources` 是归档时的测试与辅助代码；重现实际 A/B 以冻结运行时和实际变换后的源文件为准。当前工作区已有后续修改，不以工作区 diff 哈希代替运行构建身份。本组完成了该候选的功能/资源复核，连续滚动退化、其它文档矩阵、模型协同和总体 0.3.0 门槛仍未完成。
