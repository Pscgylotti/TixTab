# Piper 本地朗读加速（0.2.11，实验性）

> 0.2.35 公开轻量版请先在设置 → 本地模型管理中安装通用运行时并下载所需模型，见 [运行时安装](RUNTIME-SETUP.md)。下文保留原开发与基准记录，包内权重等描述适用于当时的完整开发包。公开轻量版不包含模型权重或 Piper 音素二进制，默认可使用系统声音。

选词 → 翻译 → 后端设置 → 朗读后端，默认“本地低功耗优先 · Piper（实验）”。AUTO 按 NPU → GPU → CPU 尝试**波形生成**，也可手动选设备，或切回内置 Piper WASM / 系统离线声音 / HTTP / 兼容语音 API。当前电脑已具备基础原生运行时；其它兼容 Windows x64 电脑可用 `backend/start-openvino.ps1 -Install` 准备。无新增 Python 依赖、声音权重或推理时网络下载。

## 实现与边界

- 复用固定 `rhasspy/piper-voices` 提交 `c10ece1aade47bb51c153c893d14e5bf8e5b7117` 的 Lessac low 英文（63,201,294 字节）与 Huayan x_low 中文（20,628,813 字节）。原始 ONNX/配置不修改，开发目录和包内提取均校验固定大小与 SHA256。首次 ASAR 提取仅取所选声音的模型和配置，缓存损坏时按校验修复。
- 复用现有 `@mintplex-labs/piper-tts-web` 1.0.5 / eSpeak WASM 音素模块。独立 worker 不初始化 ORT、不读取声音网络，复用一个音素运行时，按每个声音自身的 `phoneme_id_map` 转换。语音运行时仍含 eSpeak GPL 组件；包装层许可声明和声音数据许可不同，见 [MODELS.md](MODELS.md)。Huayan 卡片的 Unknown 数据许可与 Lessac 数据集许可仍需在重新分发前核实。
- 对照 [Piper 的音素/推理接口](https://github.com/OHF-Voice/piper1-gpl/blob/main/src/piper/voice.py)，在 `dec/conv_pre` 前拆分固定图。动态时长预测与流变换留在 CPU（两线程、一个 stream、f32，batch=1），波形解码器使用 NPU/GPU 静态 256 帧窗口，或完整动态 CPU。不是整个声音模型都在 NPU 上运行。
- 两个固定解码图的保守感受野半径计算为 12 个潜变量帧；实现使用左右各 32 帧上下文，每个窗口最多交付 192 帧。直接把潜变量补零到静态长度会改变真实尾音，因此最后 32 帧改用动态 CPU 解码，并保留前方 32 帧上下文。全程按原 hop=256 拼接，检查样本总数，不重采样、不丢弃尾部。≤64 帧的短句完全走 CPU，以避免分块调度开销。
- CPU 分块拼接与完整动态 CPU 在两声音/多个长度上的数值对照通过；完整 CPU 图与拆分图在关闭随机噪声时输出对照通过。NPU/GPU 的浮点舍入存在差异，仍标实验性。模型带随机时长/噪声，同一文本每次长度和波形可能不同，不能直接逐样本比较独立两次合成。
- 选区上限 4000 字符；音素 worker 按最多 80 个 UTF-16 单元分段，优先句末/空白，数字/缩写展开过长时继续细分，单次最多 256 段、每段 1024 个 ID、总计 65,536 个 ID；后端限制每段 4096 潜变量帧、总音频 20 分钟、推理期限 120 秒。当前整段合成后播放，长段首段即时播放仍待评估。
- `/synthesize` 返回单声道 16kHz/16bit **二进制 WAV**；小型设备/耗时元数据放在显式暴露的响应头，避免 JSON base64 的音频复制膨胀。图中非有限数值拒绝；设备失败在当前声音会话内冷却 5 分钟，AUTO 可转 GPU/CPU，整个原生服务不可用则使用真实 Piper WASM。
- Texo、OPUS、OCR、Piper 共用请求锁和单份原生模型生命周期；更换任务/声音释放旧模型，闲置 120 秒释放。每个声音至多两个 CPU 会话和 NPU/GPU 各一个解码会话；独立图版本编译缓存目标 256MiB，驱动锁文件可能暂时超限，目标不等于进程总内存。
- 原生阶段/编译前后检查取消；单次驱动调用不能中途强制停止。400/422/429/499/504、HTTP 超时和主动取消不会重复启动 WASM 或系统合成；普通原生不可用可回退 WASM，声音模型完全不可用时才尝试系统离线声音。语音前后端与设备偏好保存，远程密钥仍只在会话中。
- 暂停/继续/停止可在紧凑划词栏直接操作，加载中也可停止；音频播放时调整语速立即生效，选区变化或关闭浮窗停止旧朗读。系统声音的语速用于下次朗读。

## 验证记录

当前设备：Core Ultra 5 238V、Arc 130V、Intel AI Boost，OpenVINO 2026.2.0。实际生产窗口的中英两声音分别完成 AUTO 两次、GPU、CPU；检查实际 WAV 采样数、采样率、非静音、播放器暂停/继续和真实 WASM 回退，见 [生产资源记录](benchmarks/piper-app-prepack-20261011.json)。[最终便携 EXE 记录](benchmarks/piper-app-20261011.json) 另包括 24 秒多段中文、与 OCR/OPUS/Texo 的实际切换，以及隔离空模型目录真实 503 后的真实 WASM 合成；成品校验与完整回归见发布目录 BUILD-INFO.json。

独立复现脚本 `scripts/benchmark-native-piper.py` 使用真实应用生成的音素，记录构造耗时、每次编译/各阶段/音频时长与 RTF（合成耗时 ÷ 音频时长）；详见 [后端测量](benchmarks/piper-openvino-20261011.json)。不包含音素生成、UI 或播放，不把暖调用当首次启动，也不把这两个样本当发音准确率/韵律验收。

最终实现的两段样本，五次暖调用后端总耗时中位数：

| 路径 | 英文样本 | 中文样本 |
| --- | ---: | ---: |
| CPU 两线程 | 118.84ms | 217.15ms |
| NPU 波形 + CPU | 81.10ms | 132.93ms |
| GPU 波形 + CPU | 60.31ms | 78.32ms |

本轮使用新的空编译缓存目录，按 CPU → NPU → GPU 顺序测量；加速器首测时共享 CPU 会话已暖。各声音首次 NPU 解码器编译约 5.2/5.4 秒、GPU 约 1.4 秒，CPU 两个阶段编译合计约 1.8 秒；这些不是三个独立进程的完整冷启动。构造模型约 476/441ms 另记，观察编译缓存共 120,376,826 字节，低于 256MiB 目标。

相同真实潜变量的 NPU/GPU 对照中，最大绝对波形误差约 0.0015–0.0021、误差 RMS 约 0.00012–0.00017，参考信号 RMS 约 0.087–0.092。该对照用于检查浮点/分块误差，不替代可懂度或听感评价。

**尚未测量实际瓦特、电池续航或系统化人工听评。** AUTO 的 NPU 优先遵循用户设备偏好；GPU 更快也不直接说明耗电更低。数字、缩写、公式、长段韵律和更大真实发音集继续保留在计划中。
