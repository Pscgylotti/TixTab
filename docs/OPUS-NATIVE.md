# OPUS 原生实验与验证

> 0.2.35 公开轻量版请先在设置 → 本地模型管理中安装通用运行时并下载所需模型，见 [运行时安装](RUNTIME-SETUP.md)。下文保留原开发与基准记录，包内权重等描述适用于当时的完整开发包。公开轻量版不包含模型权重或 Piper 音素二进制，默认可使用系统声音。

0.2.8 增加可选的本地 OpenVINO 翻译。划词浮窗 → 翻译 → 后端设置 →「本地实验 · OPUS OpenVINO」。默认内置 WASM 路径保留；实验选择和设备偏好单独保存，不保存 API 密钥。

## 计算与资源策略

- 自动模式依次尝试 NPU、GPU、CPU；手动设备不可用则退回 CPU。编码器使用已下载的 q8 权重、连续浮点激活；NPU 静态输入为 16/32/64/128/256/512 token 档位，GPU/CPU 使用实际长度与 f32。
- 自回归解码使用两线程 CPU，首步/后续缓存分支分别编译。最多生成 256 token；输入切块后检查 512 token 上限，不静默截断。
- Texo 与 OPUS 共用一个本地请求锁；切换模型或翻译方向时先释放旧模型，闲置 120 秒释放。OPUS 最多保留两个编码器设备/长度配置。设备异常冷却五分钟。
- 编译缓存独立于原始权重，当前计算图/运行时版本目录目标上限 768MiB，编译前后清理旧文件。驱动锁定文件或文件系统拒绝删除时可能暂时超限；它不代表进程总内存上限。
- 复用固定版本包内模型，ASAR 首次按方向提取四个文件并验证大小/SHA256；已损坏的缓存重新提取。无新增模型下载。Python 运行时沿用 Texo 的独立安装。
- 后端不可用或旧版手动服务没有翻译能力时回退包内 WASM，不结束用户手动启动的服务。取消、忙碌、输入拒绝和超时不会另起 CPU 推理。单次底层编译/推理不能中途打断，取消在阶段之间生效。

## 已定位的数值问题

最初直接编译 q8 图在 GPU 默认精度下出现全部非有限编码输出，NPU 译文也明显失真。原始 MatMulInteger 累加结果先转浮点、后乘比例，FP16 路径可能在缩放前溢出。另一个问题是动态激活量化的范围包含 padding，注意力 mask 不会消除这部分量化影响。

实验对照采用两条图转换：先缩放有界操作数、再矩阵乘法；编码器另提供移除动态激活量化的连续激活版本。后者保留已下载 q8 权重，但改变了计算语义，不能称为与既有 WASM 模型等价。生产实验选项使用连续激活编码器和有界 q8 CPU 解码器。

原始记录：[OPUS 图与设备对照](benchmarks/opus-openvino-20261011.json)。其中 `productionVersionUnchanged: 0.2.7` 表示该记录采集时尚未接入应用；0.2.8 的成品接入记录另见本版本 BUILD-INFO.json。

## 质量边界与后续

13 个中英输入覆盖普通句子、段落、Unicode 与公式。连续激活图的最终 token 与原 ORT q8 参考完全一致：CPU 9/13、GPU 10/13、NPU 9/13；GPU 与同图 CPU 一致 12/13、NPU 11/13。这些是逐 token 一致性，既不是准确率，也不说明不一致的译文必然更差。部分差异是近义表达，部分涉及模式/术语翻译。

已有 q8 基线也存在错误，例如 Hello World 和公式符号。连续激活三种设备在一个数学样本中均将 `x^2` 输出为 `x% 2`；目前没有可靠的公式/专有名词保留策略或充分人工评测。因此此后端明确标为实验性，提示核对公式、数字和专有名词，并保留原有默认路径。

仍需完成更大的人工评审集、真实 PDF 术语/数学内容保留、端到端冷暖时延/内存对照和实际瓦特/电池测量。Piper 与文字 OCR 的原生适配继续保留在计划中。
