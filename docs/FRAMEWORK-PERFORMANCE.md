## Electron：启动、主线程与进程生命周期

[Electron 官方性能指南](https://www.electronjs.org/docs/latest/tutorial/performance)建议先测量，减少启动加载、阻塞主进程和不必要工作；持续 CPU 工作适合工作线程，小型低优先级任务可安排在空闲时执行。

当前 Electron 固定 44.7.0。设置/公式/草图/聊天等窗口已按需加载；主窗口启用 sandbox、contextIsolation，通过异步 IPC 调用。主进程仍在入口加载多种后端控制器；是否影响启动，需要采集模块加载与控制器初始化耗时。`autoHideMenuBar` 已开启，但未移除默认菜单。

## PDF.js：背景任务、文本层与内存所有权

[PDF.js 官方 FAQ](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions)建议只渲染可见页，并要求主库与 worker 版本一致；HTTP Range 是否有效取决于网络服务和加载方式。

当前版本 5.4.624，worker 从同一依赖打包。已有共享底图/瓦片队列、去重、取消、LRU、交互和隐藏暂停、连续页虚拟化。文本层按选文工具挂载，切换可能重新取文本并构建 DOM。`loadPdf` 使用完整本地 Uint8Array，保留副本供工程保存/导出，不能直接删除 `bytes.slice()` 而让 worker 转移原始缓冲区。

- [ ] 对底图、高清瓦片、缩略图、文本层及原图预览建立共享内存账本，按实际尺寸、复用次数和失效代价调节缓存；测量取消后仍完成的工作，禁止重复竞争队列。
- [x] 文档身份限定的默认文本内容缓存：最多 32 页/估计 8 MB，合并在途提取、失败重试、LRU 淘汰；每个文本层仍拥有自己的 DOM/布局，不改变 PDF.js 提取参数。字体、缩放、旋转、双栏、RTL 和反向选词原生回归及源数据只读检查通过；上方单次证据只证明所列范围。
- [ ] 后续独立评估文本 DOM 复用、布局读写分离和可访问性，保持文本源/布局的所有权；多文档总内存预算单独评估，不能将每文档 8 MB 当成全局上限。
- [ ] 大文件测量缓冲复制与 IPC 传输成本；先明确每个缓冲区的拥有者和生命周期。未来远程 URL 加载单独评估 Range/stream，本地完整缓冲加载不能靠开关 Range 提速。
- [ ] 资源回收必须等渲染终止并检查字体/图片/文本层共享关系，不能在绘制中任意 cleanup；版本升级作为独立变更，回归字体、裁剪、透明图、扫描件、夜间转换与导出。
- [ ] 核查绘制块与应用队列的共同帧预算。本地 5.4.624 的 `InternalRenderTask._continue()` 将 `_scheduleNextBound` 交给 `onContinue`；正常窗口路径的 `_scheduleNext()` 已使用 RAF，`CanvasGraphics.executeOperatorList()` 按 10 次操作检查约 15 ms 截止。15 ms 不是硬上限，单次操作、依赖恢复和多个并发任务仍可能跨越 120 Hz 的 8.33 ms 帧周期。先用独立 trace 确认同帧争用与可见页等待，再评估有界的任务轮转/优先级；不能盲目再包一层 RAF、直接修改第三方时限或将延后补绘移出完整流程测量。保持最终像素、取消、窗口恢复及后台不饿死。
  - 已完成三份独立追踪及实际 bundle 栈定位：快速双页根任务内同时出现前景 `flushSync`/几何读取、两个 PDF.js 续绘和底图复制。按实际倍率省去重复复制的候选虽减少目标任务，六轮整段资源未改善而撤回；后续检查共享几何读取、布局 effect/ResizeObserver 重复以及完成复制与续绘的有界协同，保持缓存命中首用和首帧内容完整。追踪包含自身开销，代表性栈不代表所有原生叶采样的唯一来源。[数据与限制](performance/2026-10-13-reading-scale/README.md)。
