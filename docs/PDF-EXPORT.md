# PDF 导出：结构保留与验证范围

0.2.21 导出复用源文档与页面，不重新创建仅有视觉内容的新页面。未修改的文档返回原始字节；工程始终保留源 PDF 和可编辑的笔迹/草图/公式对象。

## 已实现

- 保留原页文字、资源、MediaBox/CropBox、旋转、UserUnit、普通批注和 URI 链接。
- 保留 AcroForm 字段树、字段值、Widget 的父子关系和现有 AP 外观；删页时清理对应控件、空字段组和计算顺序引用，不调用会更新外观/删除 XFA 的高级表单接口。
- 页面重排后保留有效的本地目标；清理指向已删页的已知显式/命名跳转，处理命名目标树边界和页标签。新空白页使用当前页序号的十进制标签。
- 每个修改页追加一个 Stamp 批注外观。压力笔迹为矢量轮廓，公式/草图 PNG 按项目尺寸嵌入；独立资源和旋转/crop/UserUnit 变换不改写源内容流。逐对象再编辑仍通过工程文件。
- 未修改含签名文档返回相同字节；修改后须在应用中确认导出副本，取消不导出，原工程源文件保持不变。修改副本需要重新签名。
- 避免导出时再次使用 PDF.js 解析、逐页嵌入源页面；删除页面后回收不可达的 PDF 对象。不新增常驻任务或轮询。
- 0.2.22 将 PDF-lib 处理移至每窗口一个短期 Worker。导出显示阶段/标注页数，取消按钮或 Escape 终止；完成、失败、离开页面时同样释放。后台加载失败提示重试，不在 UI 线程重新执行同一任务。
- 准备快照时按约 6ms 时间预算让出主线程，源文件按 1MiB 分块复制；传输私有源文件/Float64 点缓冲区，已缓存的完成笔迹复用相同轮廓。工程原字节不分离，省略场景/SVG 预览/宏等编辑数据。大型 PNG 字符串仍需结构化克隆，分配与下载仍有主线程成本。

## 验证方法

`src/pdfExportClient.test.ts` 验证传输精度、源缓冲区完整、协作取消、一次终止、并发拒绝、pagehide、回调异常及失败恢复。`tests/pdf-worker.spec.ts` 使用实际 Worker 验证脚本加载失败/重试与密集笔迹帧间隔；与直接核心导出的输出逐字节比较。缓存轮廓样本未表现出总耗时下降，不以此声称更低功耗。

`scripts/verify-pdf-worker-ui.mjs` 可在 ASAR/便携 EXE 中验证取消、无取消下载、失败后重试、工程原字节、中英文/夜间/竖屏及 Worker 结束释放。仅为稳定截图暂缓传输；运行中取消在真正的 Worker 加载阶段触发。

`tests/pdf-preservation.spec.ts` 使用真实 PDF.js 渲染对照保留页面的文字、字段外观及批注；覆盖 0/90/180/270°、裁剪和 UserUnit=2。笔迹/图片的坐标测试独立排除 Widget 重排，再由 Poppler 验证覆盖表单的批注层叠。夜间图片定位也识别批注外观的矩阵，不继承前一个内容流的 CTM。

`scripts/verify-pdf-ui.mjs` 只通过应用界面操作，捕获应用生成的最终下载 Blob 后独立解析；可用于开发预览、ASAR 及真正便携 EXE。验证无修改字节一致、插页/重排/删页、笔迹与公式、重新导入后的选文、字段值/AP、原批注/URI、源工程字节和签名确认。下载 Blob 在测试中捕获，不测试系统“另存为”对话框。

`scripts/verify-pdf-preservation.py` 用 pypdf 独立检查规范字段树 `/V`、页面 Widget 的继承值、AP 内容哈希、字段状态、元数据/XMP、保留文字及已删页的文字。合成源文档由 `scripts/pdf-preservation-fixture.mjs` 提供。签名用例只有签名字典，不能证明密码学验证能力。

## 尚未完成的兼容性

- PDF.js 将 Widget 放在其它批注上方，覆盖表单的标注会被控件挡住；Poppler 按批注数组顺序绘制。不同 PDF 查看器的层叠结果可能不同，不能同时保证所有查看器显示相同且表单完全交互。
- Tagged PDF 的结构树/ParentTree、附件、XFA、复杂动作链及更多真实复杂文档尚未全面核验。保留已有引用不等于正确重排所有语义结构。
- 不支持密码学签名验证、签名增量保存或保持修改副本的原签名有效性。检测只依据签名字典。
- 加密/密码文档、重复引用同一源页、手工改变源页尺寸的工程尚未支持安全导出。相关错误明确拒绝，不静默转换成图像。
- 删除页面不是安全擦除或保密脱敏；复杂结构、附件或其它对象仍可能引用旧内容。没有进行安全擦除审计。
- 新 Stamp 外观可被支持批注的查看器关闭/删除；它不是不可修改的压平副本。请保存工程以便继续逐对象编辑。

完整需求仍在 [需求清单](REQUIREMENTS.md) 和 [实现计划](PLAN.md) 中，不将本轮的合成用例视为全部 PDF 兼容性验收。
