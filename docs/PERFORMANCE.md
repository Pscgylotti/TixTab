## 任务延长与能量比较

限制并发、削平需求峰值和降低整段能量分别验收。动态功率可近似为 `α C V² f`，但并发减少不保证降压；同工作量、同电压的理想降频主要降低功率而非动态能量，还会延长其它保持活跃的开销。频率、活跃核心、缓存/内存及操作系统策略会改变结果，不能用 CPU 占用率直接推算 W/J。

把 x 时长的任务放宽为 4x 时，采用共同 4x 观察窗口：快速方案能量为 `Pf·x + Pi·3x`，慢速为 `Ps·4x`；只有 `Ps < (Pf + 3Pi)/4` 时慢速省电。Pf/Ps/Pi 必须来自同一计量范围（例如整机），并包含实际完成后的空闲；不能省略快速完成后的空闲能耗，也不能混用 CPU 包功率与整机基线。实际任务还须覆盖完成后的尾部工作和恢复，示意常数功率不替代积分实测。

当前资源报告仍使用全进程 CPU 时间积分和 200 ms/1 s 需求代理，并保持真实功率/能量为空。优先消除重复工作，再比较有期限的并发/分片策略；只有峰值下降时不称为节能。物理模型来源：[Intel 功率模型](https://www.intel.com/content/dam/doc/white-paper/power-management-technologies-for-processor-graphics-display-and-memory-paper.pdf)、[频率/电压工作点说明](https://www.intel.com/content/www/us/en/support/articles/000007073/processors.html)；不把旧平台具体电压域结构套用到当前混合架构。

## 简单模型

`D = a·CPU时间 + b·GPU活跃时间 + c·NPU活跃时间 + d·内存传输量 + e·I/O量 + f·唤醒次数`。

当前采集链路只提供 `a=1` 的 CPU 部分需求，单位为 CPU 秒。其余项不可得时为 `null`，不能当作零；D 尚未校准为焦耳。JSON 同时保留各进程采样、阶段时间、主线程任务/布局/脚本时间、长任务和帧间隔。

由累计 CPU 时间计算相邻样本间的差值，包含阶段之间的间隙和最后静置尾部。以实际采样间隔内均匀消耗为假设，重采样到 200 ms/1 s 窗口，报告核数等效需求 P95/P99/峰值及超过一核的持续时间。窗口细分不会增加原始精度；不能据 200 ms 采样声称观察到了 50 ms 尖峰。进程在两次采样之间退出会漏计，报告标出不匹配区间。

真实能量需要 `E = ∫P_system(t)dt`，同时报告整机总值和扣除同条件空闲基线后的增量。组件能量有包含关系时不得重复相加；Windows E3 是系统估算，CPU package 不能代表整机。本轮尚无可靠整机功率记录。

## 第一项改动：提交笔迹增量合成

旧实现每次抬笔清空整页画布，再绘制全部笔迹。新 `CommittedInk` 只在旧笔迹对象引用、顺序、页 ID、页面尺寸、画布和像素尺寸均保持一致时绘制追加的尾部；移除、编辑、重排、尺寸改变、切页或画布重新挂载时完整回放。Canvas 上下文丢失时废弃增量状态，恢复事件立即回放当前笔迹。保持原画布像素上限、原始压感点、几何轮廓、透明度、绘制顺序和夜间滤镜。

`tests/ink-raster.spec.ts` 检查不同透明笔触重叠、短笔划、同 ID 内容编辑、撤销重做、擦除、尺寸上限与画布替换，并逐通道比较像素。确定性算法测试固定同一光栅后端；实际编辑器检查读取副本，避免频繁读取原 Canvas 导致浏览器从 GPU 切换至 CPU，进而在测试本身引入抗锯齿差异。断言仍为零像素差，不放宽容差。

`verify-ink-native.mjs` 在真实 Electron 中用既有路径生成器作完整回放参考，对加载、四种笔触追加、撤销重做、尾擦、夜间和视图重建作像素检查，记录 GPU 功能状态。性能采集期间不读 Canvas 像素。

## 第二项改动：包围盒层级与局部回放

使用 [RBush](https://github.com/mourner/rbush) 4.0.1（MIT）的动态二维 R-tree，实现包围盒层级的粗筛。每个挂载编辑页维护一份笔迹索引和一份对象索引；对象索引由擦除和对象选择共用，组合按顶层边界参与查询，原有内部层级不变。少于 64 项时使用包围盒线性筛选。相同数组不更新，追加只插入新项，删除/移动按不可变引用增删节点；只有首次达到阈值或大批变化时批量构建，不为撤销历史中的每份数组保存树。

笔迹边界同时覆盖实际压力轮廓（沿用两位小数路径）和原始点加半笔宽，避免漏掉原有精确擦除命中。路径和边界共用轮廓计算。尾擦用相邻采样之间的扫掠包围盒筛选，再调用原来的线段/笔迹与矩形精确判断；待删除红色高亮缓存完整路径，松手后才统一删除。对象框选保留严格边缘判断与层序，点击多选覆盖层选择最上层候选；移动/缩放和组合仍由原来的 DOM 层绘制。

删除、修改和非尾部插入时，根据新旧边界计算含抗锯齿余量的整数设备像素脏区，查询按原层序重放的剩余笔迹。脏区超过一半画布、候选超过 70%、重排、尺寸/画布变化或上下文恢复仍完整回放。输入命中索引若先于 Canvas 推进，完整回放避免遗漏中间改动。原 PDF.js 缓存/瓦片/队列不变，此索引没有改写 PDF 内部绘图操作。

直接裁剪穿过透明笔触时，即使裁剪矩形为整数像素，Skia 的边缘也会出现逐通道差异。完整笔触边界闭包原型通过像素检查，但密集场景容易扩张成整页。最终方案在候选笔触完全包含于脏区时直接回放；否则按需使用与主画布同尺寸、同变换的临时画布，不裁断路径，再 1:1 复制脏区。只清临时画布的当前脏区，区域外内容不用于合成；每次使用前检查上下文，失败回退完整绘制。代价是一份额外 RGBA 缓冲：本样本约 8.0 MB，最多约 16 MB（不含浏览器额外开销）。切页/尺寸改变、离开编辑画布和重置释放，不为每次笔划创建新画布。

单元回归覆盖随机添加、删除、移动、重排、撤销/重做、重复引用、小场景阈值、严格框选边缘，以及精确命中与全扫描一致性。CPU/GPU 光栅逐通道零差异，覆盖密集透明叠加、稀疏移动、随机删改、索引先于画布更新、同 ID 编辑与尺寸/画布变化；明确断言实际执行过临时画布路径。原生验证增加启动就绪、文档名和 500 笔导入断言，防止把导入前的空白文档误当样本。

`npm run benchmark:spatial` 独立测量同步查询内核，结果与 UI/耗电区分：固定 3000 笔、80 对象和 240 次局部查询，精确检查笔迹从 720000 条降到 3098 条；六次交错热测中位数约 549.99→2.16 ms。首次准备轮廓/边界并建树 141.12 ms，30 次追加加 30 次移除 24.25 ms；边界只新增 30 份，树仍只批量构建一次。这些是 Node 同步内核时间，不能推广为界面加速比例或节能比例；冷建立成本没有隐藏在热测之外。

本地 AI 的设备选择、编译/热模型缓存、闲置释放、线程与并发预算、静音检测和渲染资源协调已另列专项，见 [PLAN.md](PLAN.md)。当前已有上述真实语音资源基线与生命周期检查，完整资源 A/B、其它后端及整机能量对照仍未完成；保留默认 1800 秒卸载和模型质量底线。
